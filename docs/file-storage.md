# Хранение файлов

## 1. Назначение

Документ описывает стратегию хранения учебных материалов, загружаемых пользователем.

В текущем релизе реализована загрузка TXT. PDF и DOCX запланированы для следующих версий. OCR, изображения и сложная обработка мультимедиа не входят в текущий объем.

## 2. Общий подход

Backend принимает файл через REST API и сохраняет:

- сам файл в локальном файловом хранилище;
- metadata файла в таблице `study_materials`;
- извлеченный текст в `study_materials.extracted_text`, если извлечение выполнено успешно.

PostgreSQL не хранит бинарное содержимое файла.

## 3. Локальная файловая стратегия

Для локальной разработки и первой стабильной версии используется volume файловой системы.

Рекомендуемая структура:

```text
storage/
  materials/
    {userId}/
      {learningGoalId}/
        {materialId}/
          original.{extension}
```

Правила:

- имя файла на диске генерируется backend, а не берется напрямую из пользовательского ввода;
- исходное имя хранится только как metadata;
- путь или ключ файла хранится в `study_materials.storage_key`;
- frontend не получает прямой путь к файлу на диске;
- доступ к файлу проходит через backend с проверкой пользователя.

## 4. Metadata handling

Таблица `study_materials` хранит:

- `id`;
- `user_id`;
- `learning_goal_id`;
- `file_name`;
- `content_type`;
- `file_size`;
- `storage_key`;
- `extracted_text`;
- `processing_status`;
- `created_at`;
- `updated_at`.

`content_type` и расширение файла валидируются на backend.

## 5. Uploaded material lifecycle

Жизненный цикл материала:

1. Пользователь загружает файл.
2. Backend проверяет JWT и принадлежность `LearningGoal`.
3. Backend валидирует тип и размер файла. В текущей реализации принимается TXT.
4. Backend сохраняет файл в volume файловой системы.
5. Backend сохраняет metadata в `study_materials`.
6. Backend извлекает текст из TXT.
7. Backend сохраняет `extracted_text` и устанавливает `processing_status = TEXT_EXTRACTED`.
8. Выделение topics из материала запланировано как следующий шаг развития.

Статусы `processing_status`:

- `UPLOADED`;
- `TEXT_EXTRACTED`;
- `TOPICS_EXTRACTED`;
- `FAILED`.

## 6. Cleanup policy

Очистка должна учитывать БД и файловую систему.

Правила:

- при удалении материала backend сначала проверяет принадлежность данных пользователю;
- запись в БД и файл должны удаляться согласованно на уровне service;
- если файл не удалился, ошибка логируется и может быть обработана отдельной задачей очистки;
- удаление `LearningGoal` в текущей модели лучше заменять архивированием;
- потерянные файлы должны периодически проверяться вручную или отдельной будущей задачей обслуживания.

## 7. Ограничения текущего релиза

Не реализуется:

- объектное хранилище;
- антивирусное сканирование;
- PDF/DOCX extraction;
- OCR;
- обработка изображений;
- версионирование файлов;
- полнотекстовый поиск по материалам.

## 8. Миграция в объектное хранилище

При росте системы локальное хранилище можно заменить на S3-compatible объектное хранилище.

Для этого достаточно:

- заменить значение `storage_key` на ключ объекта во внутреннем хранилище;
- оставить metadata в `study_materials`;
- сохранить доступ к файлам только через backend;
- не менять доменные связи `LearningGoal`, `StudyMaterial` и `Topic`.
