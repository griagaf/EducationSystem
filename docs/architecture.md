# Architecture

## 1. Общая схема системы

Базовая версия системы состоит из четырех основных компонентов:

```text
Browser
  |
  | HTTP
  v
React Frontend
  |
  | REST API / JSON
  v
Spring Boot Backend
  |                 |
  | SQL             | REST API / JSON
  v                 v
PostgreSQL        Python FastAPI AI-service
```

Запуск системы выполняется через Docker Compose:

- `frontend` - React + Vite + TypeScript + Tailwind CSS;
- `backend` - Java 21 + Spring Boot 3.x + Gradle + Flyway;
- `ai-service` - Python 3.12 + FastAPI;
- `database` - PostgreSQL.

## 2. Ответственность слоев

### Frontend

React frontend отвечает за пользовательский интерфейс:

- регистрация и вход пользователя;
- хранение access token на клиенте в клиентском приложении;
- защищенная навигация после авторизации;
- формы создания заметок и учебных целей;
- отображение roadmap;
- отображение задач;
- изменение статуса задач;
- отображение dashboard и прогресса;
- показ состояний загрузки, пустого списка и ошибки.

Frontend не обращается напрямую к PostgreSQL и AI-service. Все бизнес-операции идут через Spring Boot backend.

### Backend

Spring Boot backend является основным приложением и центром бизнес-логики:

- регистрация пользователей;
- авторизация по JWT;
- хэширование паролей;
- проверка доступа к данным текущего пользователя;
- CRUD для заметок;
- CRUD для учебных целей;
- хранение roadmap;
- вызов AI-service для генерации roadmap;
- валидация ответа AI-service;
- автоматическое создание задач из roadmap;
- управление задачами;
- расчет прогресса;
- подготовка данных для dashboard.

Backend является единственным слоем, который работает с PostgreSQL.

### AI-service

Python FastAPI AI-service отвечает только за AI-операции без хранения состояния:

- принимает цель пользователя от backend;
- формирует структурированный roadmap;
- извлекает темы из пользовательских материалов;
- генерирует flashcards по темам и материалам;
- возвращает этапы roadmap и задачи в JSON;
- может использовать внешний LLM;
- использует graceful degradation для устойчивости работы без внешнего AI API.

AI-service не хранит пользовательские данные, не выполняет авторизацию и не подключается к PostgreSQL.

### Database

PostgreSQL хранит основные данные системы:

- пользователей;
- заметки;
- учебные цели;
- учебные материалы;
- темы;
- roadmap;
- этапы roadmap;
- задачи;
- flashcards и историю review;
- knowledge graph;
- статусы и прогресс.

В базовой версии системы PostgreSQL используется как обычная реляционная база данных. Поддержка pgvector и семантического поиска оставляется для будущих версий.

## 3. Основной поток данных

### Регистрация пользователя

1. Пользователь вводит email, имя и пароль на frontend.
2. Frontend отправляет запрос в backend.
3. Backend валидирует данные.
4. Backend проверяет уникальность email.
5. Backend хэширует пароль.
6. Backend сохраняет пользователя в PostgreSQL.
7. Backend возвращает JWT и краткие данные пользователя.
8. Frontend сохраняет token и открывает dashboard.

### Создание цели

1. Пользователь вводит учебную цель на frontend.
2. Frontend отправляет цель в backend.
3. Backend определяет текущего пользователя по JWT.
4. Backend сохраняет цель в PostgreSQL со статусом `ACTIVE`.
5. Backend возвращает созданную цель.
6. Frontend показывает цель в списке и на странице деталей.

### Генерация roadmap

1. Пользователь нажимает генерацию roadmap на странице цели.
2. Frontend отправляет запрос в backend.
3. Backend проверяет, что цель принадлежит текущему пользователю.
4. Backend собирает описание цели, темы и связанные материалы.
5. Backend отправляет структурированный запрос в AI-service.
6. AI-service возвращает roadmap, topics и task suggestions.
7. Backend валидирует roadmap.
8. Backend сохраняет roadmap, этапы и связи с topics в PostgreSQL.
9. Backend возвращает roadmap frontend.
10. Frontend отображает этапы roadmap.

### Загрузка материалов и извлечение тем

1. Пользователь загружает PDF, DOCX или TXT в рамках учебной цели.
2. Backend сохраняет metadata файла и извлеченный текст.
3. Backend отправляет текст в AI-service через `POST /api/ai/extract-topics`.
4. AI-service возвращает структурированные topics.
5. Backend сохраняет topics и связывает их с `LearningGoal` и `StudyMaterial`.
6. Roadmap может быть построен или уточнен вокруг полученных topics.

### Генерация и прохождение карточек

1. Пользователь запрашивает flashcards по цели, материалу или теме.
2. Backend вызывает AI-service через `POST /api/ai/generate-flashcards`.
3. AI-service возвращает structured JSON с вопросами и ответами.
4. Backend сохраняет flashcards и связывает их с topics.
5. Пользователь проходит карточки для самопроверки.
6. Backend сохраняет `FlashcardReview` и обновляет `Topic.mastery_score`.

### Knowledge Graph

1. Backend строит минимальный knowledge graph из goals, topics, roadmap steps и tasks.
2. Узлы и связи сохраняются в PostgreSQL.
3. Frontend получает visualization-ready структуру через backend API.
4. AI-service не хранит graph и не обращается к базе.

### Создание задач

1. После успешной генерации roadmap backend берет этапы и task suggestions из ответа AI-service.
2. Backend создает задачи в PostgreSQL.
3. Каждая задача связывается с пользователем, целью и при наличии с этапом roadmap.
4. Начальный статус задачи - `TODO`.
5. Frontend отображает задачи на странице цели.

### Отображение прогресса

1. Пользователь отмечает задачу как выполненную.
2. Frontend отправляет изменение статуса в backend.
3. Backend проверяет доступ к задаче.
4. Backend обновляет статус задачи в PostgreSQL.
5. Backend пересчитывает прогресс цели:

```text
progress = completed tasks / all tasks * 100
```

6. Backend сохраняет или возвращает актуальный прогресс.
7. Frontend обновляет progress bar на странице цели и dashboard.

## 4. Архитектурный стиль

### Модульный монолит

Spring Boot backend реализуется как модульный монолит.

Рекомендуемые модули backend:

- `auth`;
- `user`;
- `notes`;
- `learning`;
- `tasks`;
- `ai`;
- `dashboard`;
- `common`;
- `config`.

Модули разделяют ответственность внутри одного backend-приложения. Это проще для базовой функциональности, чем микросервисы, но сохраняет понятные границы для будущего развития.

### Отдельный AI-service

AI-генерация вынесена в отдельный FastAPI сервис, потому что:

- Python удобен для AI-интеграций;
- AI-логику можно развивать независимо от Java backend;
- backend не зависит от конкретного LLM-провайдера;
- AI-service можно заменить или расширить без изменения основной бизнес-логики.

### REST API между слоями

Взаимодействие между компонентами выполняется через REST API:

- frontend вызывает backend через `/api/v1`;
- backend вызывает AI-service через внутренние endpoints `/api/ai`;
- backend работает с database через SQL/JPA.

Frontend не вызывает AI-service напрямую.

## 5. Базовая функциональность

Core functionality включает:

- регистрация пользователя;
- вход пользователя;
- JWT-авторизация;
- заметки пользователя;
- учебные цели с типами `SELF_STUDY`, `EXAM_PREPARATION`, `INTERVIEW_PREPARATION`, `TECHNOLOGY_LEARNING`;
- загрузка и обработка учебных материалов;
- извлечение тем из материалов;
- генерация roadmap через AI-service;
- хранение roadmap;
- этапы roadmap;
- автоматическое создание задач из roadmap;
- flashcards и история review;
- базовая explainable-оценка mastery level по topics;
- минимальный knowledge graph;
- ручное изменение статуса задач;
- расчет прогресса по задачам;
- dashboard с прогрессом;
- минимально аккуратный frontend;
- запуск через Docker Compose.

## 6. Что запланировано для следующих версий

Для следующих версий запланированы:

- семантический поиск по заметкам и roadmap;
- pgvector embeddings;
- расширенный knowledge graph и графовая аналитика;
- календарь и планирование по датам;
- персональные рекомендации;
- мобильное приложение;
- командная работа;
- роли администратора;
- уведомления в реальном времени;
- загрузка файлов;
- сложная ML-система;
- Kubernetes;
- микросервисная декомпозиция всего backend.

## 7. Расширение после первой стабильной версии

После первой стабильной версии архитектуру можно развивать без полного переписывания:

- добавить pgvector в PostgreSQL для семантического поиска;
- добавить embeddings для заметок и этапов roadmap;
- построить knowledge graph поверх целей, тем и заметок;
- добавить календарный вид задач;
- добавить рекомендации на основе прогресса;
- вынести отдельные модули из backend в сервисы только при реальной необходимости.
