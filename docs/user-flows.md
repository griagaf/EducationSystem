# User Flows

## 1. Регистрация и вход

### Актор

Новый или существующий пользователь.

### Предусловия

- Пользователь открыл frontend-приложение.
- Backend и database доступны.
- Для регистрации email пользователя еще не занят.

### Шаги пользователя

1. Пользователь открывает страницу регистрации.
2. Пользователь вводит display name, email и пароль.
3. Пользователь отправляет форму регистрации.
4. Если аккаунт уже существует, пользователь открывает страницу входа.
5. Пользователь вводит email и пароль.
6. Пользователь отправляет форму входа.

### Действия системы

1. Frontend валидирует обязательные поля.
2. Frontend отправляет запрос в Auth API.
3. Backend проверяет корректность данных.
4. Backend проверяет уникальность email при регистрации.
5. Backend хэширует пароль.
6. Backend создает пользователя и профиль.
7. Backend генерирует JWT.
8. Frontend сохраняет JWT.
9. Frontend перенаправляет пользователя на dashboard.

### Результат

- Пользователь авторизован.
- JWT сохранен на клиенте.
- Пользователь видит dashboard.

### Возможные ошибки

- Email уже занят.
- Некорректный email.
- Слишком короткий пароль.
- Неверный email или пароль при входе.
- Backend недоступен.
- JWT не удалось сохранить или проверить.

## 2. Создание заметки

### Актор

Авторизованный пользователь.

### Предусловия

- Пользователь вошел в систему.
- JWT валиден.
- Пользователь находится на странице Notes.
- Если заметка привязывается к цели, эта цель уже создана и принадлежит пользователю.

### Шаги пользователя

1. Пользователь открывает раздел Notes.
2. Пользователь нажимает создание заметки.
3. Пользователь вводит title и content.
4. Пользователь опционально выбирает учебную цель.
5. Пользователь сохраняет заметку.

### Действия системы

1. Frontend проверяет, что title и content не пустые.
2. Frontend отправляет запрос в Notes API.
3. Backend проверяет JWT.
4. Backend определяет текущего пользователя.
5. Backend проверяет, что выбранная учебная цель принадлежит пользователю.
6. Backend сохраняет заметку в PostgreSQL.
7. Backend возвращает созданную заметку.
8. Frontend обновляет список заметок.

### Результат

- Заметка создана.
- Заметка отображается в списке Notes.
- Если выбрана цель, заметка связана с этой учебной целью.

### Возможные ошибки

- JWT отсутствует или истек.
- Title пустой.
- Content пустой.
- Выбранная учебная цель не найдена.
- Пользователь пытается привязать заметку к чужой цели.
- Backend или database недоступны.

## 3. Создание учебной цели

### Актор

Авторизованный пользователь.

### Предусловия

- Пользователь вошел в систему.
- JWT валиден.
- Пользователь находится на странице Learning Goals.

### Шаги пользователя

1. Пользователь открывает раздел Learning Goals.
2. Пользователь нажимает создание цели.
3. Пользователь вводит название цели.
4. Пользователь вводит описание цели.
5. Пользователь указывает длительность или целевую дату.
6. Пользователь сохраняет цель.

### Действия системы

1. Frontend валидирует обязательные поля.
2. Frontend отправляет запрос в Learning Goals API.
3. Backend проверяет JWT.
4. Backend определяет текущего пользователя.
5. Backend создает учебную цель со статусом `ACTIVE`.
6. Backend устанавливает начальный прогресс `0`.
7. Backend сохраняет цель в PostgreSQL.
8. Backend возвращает созданную цель.
9. Frontend показывает цель в списке.

### Результат

- Учебная цель создана.
- Цель отображается на странице Learning Goals.
- Пользователь может открыть детали цели и сгенерировать roadmap.

### Возможные ошибки

- JWT отсутствует или истек.
- Название цели пустое.
- Описание цели пустое.
- Длительность указана некорректно.
- Целевая дата указана некорректно.
- Backend или database недоступны.

## 4. Генерация roadmap через AI

### Актор

Авторизованный пользователь.

### Предусловия

- Пользователь вошел в систему.
- JWT валиден.
- Учебная цель существует.
- Учебная цель принадлежит текущему пользователю.
- Backend доступен.
- AI-service доступен или включен режим graceful degradation.

### Шаги пользователя

1. Пользователь открывает страницу учебной цели.
2. Пользователь нажимает кнопку генерации roadmap.
3. Пользователь ожидает завершения генерации.

### Действия системы

1. Frontend показывает состояние загрузки.
2. Frontend отправляет запрос в Roadmap API.
3. Backend проверяет JWT.
4. Backend проверяет, что цель принадлежит текущему пользователю.
5. Backend формирует запрос к AI-service.
6. AI-service валидирует входные данные.
7. AI-service вызывает AI-провайдера или механизм graceful degradation.
8. AI-service возвращает структурированный JSON.
9. Backend валидирует AI-ответ.
10. Backend сохраняет roadmap.
11. Backend сохраняет roadmap steps.
12. Backend инициирует автоматическое создание задач.
13. Backend возвращает roadmap и созданные задачи.
14. Frontend скрывает состояние загрузки и отображает roadmap.

### Результат

- Roadmap создан и сохранен.
- Этапы roadmap отображаются на странице цели.
- Для этапов созданы задачи.

### Возможные ошибки

- JWT отсутствует или истек.
- Цель не найдена.
- Цель принадлежит другому пользователю.
- Roadmap уже существует, если повторная генерация запрещена.
- AI-service недоступен.
- AI-провайдер вернул некорректный ответ.
- Истекло время ожидания ответа AI-service.
- AI вернул пустой результат.
- Backend не смог сохранить roadmap.

## 5. Автоматическое создание задач

### Актор

Система.

### Предусловия

- Пользователь запустил генерацию roadmap.
- AI-service вернул валидный roadmap.
- Roadmap и steps успешно сохранены.
- Ответ AI-service содержит tasks или данные, из которых backend может создать задачи.

### Шаги пользователя

Пользователь не выполняет отдельные действия. Создание задач происходит автоматически после генерации roadmap.

### Действия системы

1. Backend получает список task suggestions из AI-ответа.
2. Backend связывает каждую задачу с текущим пользователем.
3. Backend связывает каждую задачу с учебной целью.
4. Backend связывает задачу с roadmap step, если указан step number.
5. Backend устанавливает статус задачи `TODO`.
6. Backend устанавливает priority, по умолчанию `MEDIUM`.
7. Backend сохраняет задачи в PostgreSQL.
8. Backend пересчитывает прогресс цели.
9. Backend возвращает список созданных задач frontend.

### Результат

- Задачи созданы автоматически.
- Задачи отображаются на странице roadmap и в общем разделе Tasks.
- Прогресс цели остается `0`, если все задачи имеют статус `TODO`.

### Возможные ошибки

- AI-ответ не содержит задач.
- Task suggestion ссылается на несуществующий roadmap step.
- Ошибка сохранения задач в database.
- Некорректный статус или priority.
- Roadmap был сохранен, но задачи создать не удалось.

## 6. Выполнение задач

### Актор

Авторизованный пользователь.

### Предусловия

- Пользователь вошел в систему.
- JWT валиден.
- У пользователя есть созданные задачи.
- Задачи принадлежат текущему пользователю.

### Шаги пользователя

1. Пользователь открывает страницу Roadmap Details или Tasks.
2. Пользователь выбирает задачу.
3. Пользователь меняет статус задачи на `IN_PROGRESS` или `DONE`.
4. Пользователь повторяет действие для других задач.

### Действия системы

1. Frontend отправляет request на изменение статуса задачи.
2. Backend проверяет JWT.
3. Backend проверяет, что задача принадлежит текущему пользователю.
4. Backend обновляет статус задачи.
5. Если статус стал `DONE`, backend устанавливает `completed_at`.
6. Если статус изменился с `DONE` на другой, backend очищает или пересчитывает `completed_at`.
7. Backend пересчитывает прогресс учебной цели.
8. Backend обновляет прогресс цели.
9. Backend возвращает обновленную задачу и новый прогресс.
10. Frontend обновляет список задач и progress bar.

### Результат

- Статус задачи обновлен.
- Прогресс цели пересчитан.
- Dashboard и страница цели показывают актуальный прогресс.

### Возможные ошибки

- JWT отсутствует или истек.
- Задача не найдена.
- Задача принадлежит другому пользователю.
- Передан недопустимый статус.
- Ошибка сохранения задачи.
- Ошибка пересчета прогресса.

## 7. Просмотр dashboard

### Актор

Авторизованный пользователь.

### Предусловия

- Пользователь вошел в систему.
- JWT валиден.
- Backend и database доступны.

### Шаги пользователя

1. Пользователь открывает Dashboard.
2. Пользователь просматривает сводные показатели.
3. Пользователь открывает цель или задачу из dashboard при необходимости.

### Действия системы

1. Frontend отправляет запрос в Dashboard API.
2. Backend проверяет JWT.
3. Backend определяет текущего пользователя.
4. Backend получает количество активных целей.
5. Backend получает количество завершенных целей.
6. Backend получает количество заметок.
7. Backend получает общее количество задач.
8. Backend получает количество выполненных задач.
9. Backend рассчитывает общий прогресс.
10. Backend получает ближайшие задачи.
11. Backend возвращает dashboard summary.
12. Frontend отображает карточки статистики, progress bars и списки.

### Результат

- Пользователь видит общую картину обучения.
- Пользователь видит активные цели и ближайшие задачи.
- Пользователь может перейти к деталям цели или задачам.

### Возможные ошибки

- JWT отсутствует или истек.
- Backend недоступен.
- Database недоступна.
- Ошибка агрегации данных.
- У пользователя нет целей или задач, тогда frontend показывает empty state.

## 8. Просмотр прогресса по цели

### Актор

Авторизованный пользователь.

### Предусловия

- Пользователь вошел в систему.
- JWT валиден.
- Учебная цель существует.
- Цель принадлежит текущему пользователю.
- У цели есть задачи или roadmap.

### Шаги пользователя

1. Пользователь открывает Learning Goals.
2. Пользователь выбирает конкретную цель.
3. Пользователь просматривает progress bar цели.
4. Пользователь просматривает roadmap steps.
5. Пользователь просматривает задачи по этапам.

### Действия системы

1. Frontend запрашивает детали цели.
2. Backend проверяет JWT.
3. Backend проверяет принадлежность цели пользователю.
4. Backend получает цель.
5. Backend получает roadmap, если он создан.
6. Backend получает roadmap steps.
7. Backend получает задачи цели.
8. Backend возвращает данные frontend.
9. Frontend отображает progress bar, roadmap и задачи.

### Результат

- Пользователь видит прогресс конкретной цели.
- Пользователь понимает, какие этапы и задачи уже выполнены.
- Пользователь может продолжить выполнение задач.

### Возможные ошибки

- JWT отсутствует или истек.
- Цель не найдена.
- Цель принадлежит другому пользователю.
- Roadmap еще не создан.
- У цели нет задач.
- Backend или database недоступны.

## 9. Загрузка учебного материала и извлечение тем

### Актор

Авторизованный пользователь.

### Предусловия

- Пользователь вошел в систему.
- Учебная цель существует и принадлежит пользователю.
- Файл имеет формат PDF, DOCX или TXT.

### Шаги пользователя

1. Пользователь открывает страницу материалов цели.
2. Пользователь загружает файл.
3. Пользователь запускает извлечение тем.
4. Пользователь просматривает созданные topics.

### Действия системы

1. Frontend отправляет файл в backend.
2. Backend проверяет JWT и принадлежность цели пользователю.
3. Backend сохраняет metadata материала.
4. Backend извлекает текст упрощенным extractor.
5. Backend вызывает AI-service `POST /api/ai/extract-topics`.
6. AI-service возвращает структурированный topics JSON.
7. Backend сохраняет topics и связывает их с целью и материалом.
8. Frontend отображает topics и mastery score.

### Результат

- Материал сохранен.
- Текст извлечен.
- Topics созданы и доступны для roadmap, tasks и flashcards.

### Возможные ошибки

- Неподдерживаемый формат файла.
- Текст не удалось извлечь.
- AI-service недоступен.
- AI-service вернул невалидный JSON.
- Пользователь пытается загрузить материал в чужую цель.

## 10. Генерация и прохождение flashcards

### Актор

Авторизованный пользователь.

### Предусловия

- Пользователь вошел в систему.
- У цели есть topics.
- Topics принадлежат текущему пользователю.

### Шаги пользователя

1. Пользователь открывает раздел flashcards цели.
2. Пользователь выбирает topics.
3. Пользователь запускает генерацию карточек.
4. Пользователь проходит карточки.
5. Пользователь отмечает результат review: `KNOW`, `PARTIAL`, `DONT_KNOW`.

### Действия системы

1. Backend проверяет принадлежность цели пользователю и topics.
2. Backend вызывает AI-service `POST /api/ai/generate-flashcards`.
3. AI-service возвращает structured flashcards JSON.
4. Backend сохраняет flashcards.
5. Backend сохраняет `FlashcardReview` после ответа пользователя.
6. Backend обновляет `Topic.mastery_score` по explainable rules.
7. Frontend обновляет карточки и mastery score.

### Результат

- Flashcards созданы.
- История review сохранена.
- Mastery score темы обновлен.

### Возможные ошибки

- У цели нет topics.
- AI-service недоступен.
- AI-service вернул некорректные flashcards.
- Flashcard не найдена или принадлежит другому пользователю.
- Review result недопустим.

## 11. Просмотр knowledge graph

### Актор

Авторизованный пользователь.

### Предусловия

- Пользователь вошел в систему.
- Учебная цель существует.
- У цели есть topics, roadmap steps или tasks.

### Шаги пользователя

1. Пользователь открывает knowledge graph цели.
2. Пользователь просматривает nodes и edges.
3. Пользователь выбирает topic node для перехода к задачам или flashcards.

### Действия системы

1. Frontend запрашивает `GET /api/v1/goals/{id}/knowledge-graph`.
2. Backend проверяет JWT и принадлежность цели пользователю.
3. Backend строит или читает visualization-ready graph.
4. Backend возвращает nodes и edges.
5. Frontend отображает graph.

### Результат

- Пользователь видит структуру цели, тем, roadmap steps и tasks.
- Graph помогает понять связи между изучаемыми темами.

### Возможные ошибки

- Цель не найдена.
- Graph еще пуст.
- Пользователь пытается открыть graph чужой цели.
- Backend не смог построить graph.
